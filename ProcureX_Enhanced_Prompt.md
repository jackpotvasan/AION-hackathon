## 1. CORE VISION (unchanged from original — do not dilute)

ProcureX must not simply compare vendor quotations by lowest price. It must:

1. Digitize and manage the full procurement lifecycle.
2. Extract structured data from vendor quotations (AI/OCR).
3. Normalize quotations across vendors/formats.
4. Calculate **true procurement cost** (not just quoted price).
5. Evaluate vendor performance & reliability.
6. Evaluate business, operational, financial, and cybersecurity risk.
7. Detect anomalies and inconsistencies.
8. Detect potential vendor impersonation.
9. Detect potential duplicate invoices.
10. Detect potential coordinated/suspicious bidding patterns.
11. Recommend the vendor with the best **overall value**.
12. Explain every recommendation (Explainable AI).
13. Predict future procurement risks.
14. Support what-if simulation.
15. Keep humans in control of every critical decision.
16. Generate purchase orders only after proper approval.
17. Integrate procurement with inventory and finance.

**Core differentiator to repeat throughout the build:**
Lowest Price ≠ Lowest True Cost ≠ Lowest Risk ≠ Best Decision.

## 2. GLOSSARY (new — prevents ambiguity across sessions)

| Term | Meaning |
|---|---|
| **True Cost** | Base price + tax + shipping + installation + maintenance + risk-adjusted delay cost − discounts. Fully explainable, never invented. |
| **FACT** | Directly verifiable system data (e.g., "quoted price = ₹50,000"). |
| **RISK INDICATOR** | A signal that raises concern but is not proof (e.g., domain mismatch). |
| **ANOMALY** | Statistically or rule-based unusual pattern, not necessarily wrongdoing. |
| **PREDICTION** | Model/statistical forecast with confidence interval — never guaranteed. |
| **AI INFERENCE** | A conclusion generated by AI reasoning over data — always labeled as such, never presented as fact. |
| **Confidence Threshold** | Configurable cutoff below which AI output requires mandatory human review. |

Every AI-generated output shown to a user **must be tagged** with one of these five labels.

5. **Auth & RBAC** — registration/login, password hashing, JWT/OAuth2, refresh strategy, RBAC, MFA-ready design. Every authorization failure must be tested (expect 403).
6. **Core Procurement MVP** — Vendor Mgmt → Product Mgmt → Purchase Request → RFQ → Quote Mgmt (build strictly in this sub-order).

Never declare a vendor "malicious" from a score alone.
18. **Vendor Impersonation Detection** — compare registered vs. incoming identity/domain/contact/payment info; flag as "POTENTIAL VENDOR IDENTITY MISMATCH," require verification, never auto-label fraud.
19. **Anomaly Detection** — rules + statistics first, ML later once data volume justifies it; every alert must include a plain-language explanation.
20. **Document Inconsistency Detection** — math mismatches, quantity/tax/total mismatches, structural red flags → "DOCUMENT INCONSISTENCY DETECTED" → human review.
21. **Duplicate Invoice Detection** — compare invoice number/vendor/amount/date/PO/line items/hash/similarity; flag, never auto-accuse fraud.
22. **Suspicious Bidding Pattern Detection** — pricing similarity, timing patterns, repeated vendor combos → "Potential coordinated bidding pattern detected — requires human investigation." Never state "fraud confirmed" without verified evidence from an authorized process.

## 10. AI SECURITY — DETAILED CONTROLS *(expanded from original)*

All vendor documents and any free-text AI input are **untrusted** by default.

```
Untrusted Input → Validation → Isolation → Parsing/OCR → Structured Extraction
→ Schema Validation → Business Rules → Authorization → Human Approval → Execution
```

Specific controls to implement:
- **Prompt-injection defense:** never let extracted document text be interpreted as system/tool instructions; keep document content strictly in a "data" role, never concatenated into system prompts unescaped.
- **Tool/function allow-listing:** the AI Copilot may only call a fixed, explicitly defined set of read-only retrieval tools scoped to the requesting user's permissions — no dynamic/free-form DB queries.
- **Output containment:** AI-generated text is never rendered as executable code, HTML, or shell commands without sanitization.
- **No irreversible AI actions:** AI must never directly trigger payments, PO issuance, vendor blocking, account changes, or permission changes — always routed through the human-approval workflow.
- **Sensitive-data leakage prevention:** redact or exclude secrets, credentials, and unrelated users' data from any AI context window.
- **Adversarial testing:** include prompt-injection and data-exfiltration attempts explicitly in the QA phase (§Phase 35).
